# Methods and Caveats

Rubin Night Watch is currently a synthetic-data demonstration of how Rubin-like alert streams could be visualized as a cosmic weather map. It does not display live Rubin alerts or confirmed astronomical discoveries.

## What the Demo Shows

The v0.1 dataset is generated by local Python scripts. It contains alert-like records, object-level JSON files, light curves, and synthetic WebP cutouts. The frontend consumes those static files directly; there is no backend API, database, authentication system, or live alert stream.

The demo is intended for product prototyping, education, and interface testing. It is not a scientific alert broker.

## Synthetic Data Generation

`scripts/generate_demo_data.py` creates:

- 20,000 synthetic alert points.
- 200 detailed object files.
- Six illustrative object classes:
  - `variable_star`
  - `asteroid`
  - `supernova_candidate`
  - `agn`
  - `artifact`
  - `unknown_anomaly`

Each synthetic class has a simple behavior model:

- Variable stars receive repeated detections with periodic-like brightness changes.
- Asteroids receive detections with small RA/Dec drift.
- Supernova candidates brighten and then fade in a simplified transient shape.
- AGN vary stochastically over time.
- Artifacts are sparse, image-like, and scientifically downweighted.
- Unknown anomalies are deliberately unusual and low-confidence.

These behaviors are designed to create plausible UI test data, not physically complete simulations.

## Scores

The anomaly and priority scores are transparent heuristics.

Anomaly score combines unusual light-curve behavior, fast change, low classification confidence, rare context, and isolation.

Priority score combines anomaly score, brightness observability, broad scientific interest, and an artifact penalty.

These scores should be read only as demo triage signals. They are not trained scientific classifiers and are not evidence of real astronomical discovery.

## Cutouts

`scripts/generate_demo_cutouts.py` creates synthetic reference, new, and difference WebP images for featured objects. They are drawn with simple image-generation rules using Pillow and NumPy:

- reference images contain synthetic star fields and optional host-like context;
- new images add transient, moving, variable, or artifact-like signals;
- difference images emphasize the simulated change.

The cutouts are not survey images and should always be labeled as synthetic demo cutouts.

## Validation

`scripts/validate_demo_data.py` checks the generated schema before the frontend consumes it. It validates required fields, RA/Dec ranges, score ranges, class labels, object IDs, detailed object files, light curves, class probability sums, and declared cutout paths.

## Public Caveats

The UI and documentation must keep the following claims clear:

- This is synthetic demo data.
- This is not live Rubin Observatory data.
- The object classes are illustrative.
- The scores are heuristic.
- The cutouts are synthetic.
- No confirmed discoveries are shown.
- Future work may add broker-like or survey-derived data through an adapter, but v0.1 is static-data only.

Recommended public wording:

> Rubin Night Watch is currently a synthetic-data demonstration of how Rubin-like alert streams could be visualized as a cosmic weather map. It does not display live Rubin alerts or confirmed astronomical discoveries.
